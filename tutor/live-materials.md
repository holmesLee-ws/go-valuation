# 실시간 시각 자료

이 리포에는 미리 만든 자료가 없다. 모든 HTML은 지금 이 학습자와의 대화에서 처음부터 만든다. 틀을 복사하지 않는다. 앞서 만든 페이지의 레이아웃도 재사용하지 않고, 그 개념에 맞는 형태를 새로 고른다.

## 언제 만드는가

전체 경로나 빈틈 경로로 진행하는 모듈에서는 **도식이 든 HTML을 최소 하나 만든다.** 탐침만으로 건너뛰는 모듈에는 만들지 않는다.

그 안에서는 개념에 구조, 흐름, 시간 변화, 비교가 있을 때, 또는 학습자의 머릿속 모델을 눈으로 꺼내 볼 필요가 있을 때 만든다. 한 줄로 답할 수 있으면 채팅으로 끝낸다.

페이지는 학습자의 답을 받아 자란다. 학습자의 답이 그림과 관련되면 그 내용을 담아 고치거나 다음 페이지를 만든다.

## 학습자와 함께 만든다

완성본을 내밀지 않는다. 전체 경로 모듈에서는 **학습자가 말한 모델을 그리는 과정을 한 번 이상 거친다.** 슬라이더 같은 조작만 있는 페이지는 함께 만든 것으로 치지 않는다. 그 밖에는 다음 중 맞는 방식을 고른다.

- 먼저 「어떻게 생겼을 것 같아요?」라고 묻고, **학습자가 말한 모델을 그대로 그린다.** 그다음 함께 어긋난 곳을 고친다.
- 학습자가 다음에 무엇을 바꾸고 볼지 정하게 하고, 그 자리에서 페이지에 더한다.
- 학습자의 실제 업무 숫자(회사명·개인 정보를 지운 것)나 DART 공시 숫자를 그림에 넣는다.
- 움직이는 값(슬라이더, 단계 넘기기, 입력 칸)을 두되, 조작하기 전에 결과를 먼저 예측해 말하게 한다. 예측·조작·설명은 **서로 다른 차례**로 둔다: ① 예측을 묻는다 → ② 답을 받으면 조작만 부탁하고 「본 숫자를 알려 주세요」 하나로 끝낸다 → ③ 그 숫자를 받은 뒤 이유를 묻는다.
- 학습자가 가정 하나를 고르면 그 값으로 페이지를 고쳐 결과가 어떻게 움직이는지 예측하게 한다.

## 재료를 조합한다

- **도식**: 인라인 SVG와 CSS로 직접 그린다. 상태가 변하는 개념은 JavaScript로 움직이게 한다.
- **조사 자료**: 사실, 수치, 역사, 최신 동향이거나 확신이 없으면 WebSearch·WebFetch로 확인한다. 공식 문서와 1차 자료를 우선한다. 페이지에 출처 URL과 조회일을 적는다.
- **이미지**: 실제 사진·역사 자료가 이해를 돕는다면 재사용 조건이 명확한 것(Wikimedia Commons, 공공 도메인 등)을 찾아 쓴다. 페이지에 출처와 라이선스를 적는다. 이미지 생성 도구가 있으면 써도 되지만 생성했다고 밝힌다.
- 데이터, 스크린샷, 인용을 지어내지 않는다. 튜터가 지어낸 값은 페이지에 「예시 값」이라고 표시한다.
- **법령·기준**을 페이지에 적을 때는 근거 규칙을 따르고, 출처 원장 id나 공식 URL과 확인 날짜를 페이지 아래에 적는다.
- **계산**이 든 페이지는 입력·가정·중간값·결과를 화면에 보여 준다. 슬라이더로 값을 바꾸는 페이지도 바뀐 중간값을 함께 보인다. 가치평가 도식의 흔한 형태(예: 기업가치→지분가치 다리, 민감도 격자, 권리 배분 폭포, 접근법별 가치 범위 비교)는 참고일 뿐, 그 개념과 학습자의 답에 맞는 형태를 새로 고른다.

## 파일

- 위치: `learner/studio/<모듈id>-<주제>/NN-<내용>.html`. 모듈에 속하지 않는 첫 지도 같은 페이지는 `learner/studio/map/`에 둔다. 경로에 공백을 쓰지 않는다. 설치나 빌드 없이 파일 하나로 열려야 한다.
- 외부 스크립트를 불러오지 않는다. 필요한 코드는 페이지 안에 직접 쓴다.
- 같은 아이디어를 발전시킬 때는 같은 파일을 고치고 새로고침을 부탁한다. 아이디어가 바뀌면 새 파일을 만든다.
- 파일 안에 아직 답하지 않은 질문의 답을 적지 않는다. 첫 화면은 방금 낸 질문의 값으로 결과를 계산해 보여 주지 않고, 칸 번호나 이름표처럼 답을 바로 읽을 수 있는 표시도 두지 않는다. 답을 보여 주는 내용은 학습자가 답한 뒤에 더하거나, 예측한 뒤 버튼으로 연다.

## 여는 법

채팅에 작업 폴더 기준 상대 경로를 적는다. Claude Desktop에서는 그 경로를 클릭해 Browser 창에서 볼 수 있다.

그리고 운영체제에 맞는 명령으로 **파일마다 처음 한 번** 열어 준다. 같은 파일을 고쳤을 때는 다시 열지 않고 새로고침을 부탁한다.

- macOS: `open learner/studio/...`
- Linux: `xdg-open learner/studio/...`
- Windows Git Bash: `start "" learner/studio/...`
- Windows PowerShell: `Start-Process learner/studio/...`

이 명령에는 작업 폴더 기준 상대 경로를 그대로 쓰고(절대 경로 금지) `.html` 파일만 연다. 다른 명령이 거부됐다는 이유로 여는 시도를 건너뛰지 않는다. 열리지 않으면 경로를 알려 주고 넘어간다. 시각 자료는 학습의 수단이므로, 여는 문제로 세션을 멈추지 않는다.

## 점검

- 글자가 겹치거나 잘리지 않는지, 화살표가 맞는 곳을 가리키는지 코드를 보며 확인한다.
- 이 페이지를 보고 학습자가 무엇을 하게 되는지 한 문장으로 말할 수 없으면 만들지 않는다.
- 브라우저 도구가 있으면 화면을 찍어 확인한다.

## 근거

Dunlosky 외(2013)는 다시 읽기의 효용을 낮게, 스스로 인출하는 연습의 효용을 높게 평가했다. 페이지를 보는 데서 끝내지 않고 예측·설명하게 하는 규칙은 여기서 유추한 것이며, 시각 자료 조작 자체를 평가한 연구는 아니다.
